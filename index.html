01Introduction

A homelab, drawn as a map

A homelab is a handful of computers at home doing jobs people usually rent from big companies: storing files, streaming movies, running a game server.

This page is a map of mine. Each shape above is one machine or service, and the lines show how they connect. Tap a part of the map, or keep scrolling.

A small self-hosted stack: a Windows workstation, an Ubuntu server, a Synology NAS and a set of Raspberry Pis behind one gateway.

Ingress
Cloudflare Tunnel, no inbound port forwards
Auth
Cloudflare Access single sign-on
This page
Static HTML on GitHub Pages; status checks run in your browser

I'm a cyber security analyst, and this is where I practice. Most of it started as "I wonder if I can host that myself," and a surprising amount of it worked.

Some of it broke at 2 a.m. That's part of it too.

02The front door

One door, checked by a bouncer

Before anyone reaches a service, they come through one front door. A bouncer at that door checks who you are.

If you're on the list, you get in. If you're not, you never even see what's inside.

Cloudflare Tunnel connects outbound from inside the network, so nothing listens on the home IP. Cloudflare Access puts single sign-on in front of each private app, and the Launcher lists every app a signed-in user may open.

Path
Browser → Cloudflare edge → Access policy → tunnel → app
Domain
DNSSEC on, DMARC enforced

The tunnel was the moment this stopped feeling scary. Nothing is exposed at home, and I can still reach everything from anywhere.

03The network

Quiet traffic control

Every device at home asks for directions before it goes anywhere online. A tiny computer answers those questions, and it refuses to give directions to ads and trackers.

The gateway handles routing and DHCP. DNS goes to Pi-hole, which forwards to Unbound as a local recursive resolver. Lookups don't depend on a third-party DNS provider, and ad and tracker domains are blocked for every device on the network.

Query
Device → Pi-hole → Unbound → root servers

The day I turned on network-wide blocking, everything in the house got faster. Nobody noticed, which is exactly how infrastructure should work.

04Media

Movie night that never buffers

The NAS is a big box of hard drives. Jellyfin turns what's on it into your own streaming service, and Seerr is the suggestion box where you ask for something new.

Media lives on the Synology NAS. Jellyfin serves libraries and playback; Seerr takes requests and shows their progress. The NAS status chip checks Jellyfin's health endpoint from your browser.

This is the part my friends actually use. They don't care how it works. They care that it works.

05Minecraft

A world that's always on

A computer at home runs a Minecraft world all day. Friends can join from a PC, a phone or a console.

One server takes both Java Edition and Bedrock Edition players. The status line asks three public server-status APIs in turn, then lists who's online.

Running a game server for friends taught me more about uptime than any class did.

06LED dashboard

A 64×64 window into the lab

A board of 4,096 tiny lights hangs on the wall and shows the time and whatever else I tell it to. The one here is a copy you can poke.

A 64×64 HUB75 RGB matrix driven by a Raspberry Pi 4. It renders clocks, scrolling text and status panels. The version on this page is a software copy drawn on a canvas.

My favorite project. It's useless in the best way.

07The lab bench

Breaking things on purpose

Security people learn by trying to break things, safely, on their own equipment. This is the corner of the lab where I do that, including testing whether AI chatbots can be tricked.

Vulnerability scanning of my own hosts and images, plus an LLM Scanner: a Gradio front end that runs garak, Promptfoo and PyRIT against local models to probe for prompt injection and jailbreaks. A software-defined radio Pi listens to the airwaves.

Studying for Network+ and Security+ goes a lot faster when there's something real to poke at.
