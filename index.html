01Introduction

A homelab, drawn as a map of the machines that run it

A homelab is a handful of computers at home doing jobs people usually rent from big companies: storing files, streaming movies, running a game server.

Each shape on this map is one machine or service. The lines show how they connect.

The next seven chapters walk through it, one part at a time.

01Introduction
Runs on7 machines · 1 gateway

A small self-hosted stack with one way in

A Windows workstation, an Ubuntu server, a Synology NAS and a set of Raspberry Pis sit behind one gateway. Public apps are published through Cloudflare, never through open ports.

Browser → Cloudflare edge → Access policy → tunnel → app
  • Ingress: Cloudflare Tunnel, with no inbound port forwards.
  • Auth: Cloudflare Access single sign-on in front of private apps.
  • This page: static HTML on GitHub Pages. The status checks run in your browser.
01Introduction

Is everything up?

NAS is online. Minecraft is sleeping. Nothing is on fire.

I'm a cyber security analyst, and this is where I practice. Most of it started as "I wonder if I can host that myself," and a surprising amount of it worked. Some of it broke at 2 a.m. That's part of it too.

02Front door

One door with a bouncer

Before anyone reaches a service, they come through one front door. A bouncer at that door checks who you are.

If you're on the list, you get in. If you're not, you never even see what's inside.

02Front door
Runs onCloudflare

Outbound tunnels and an identity check at the edge

Cloudflare Tunnel connects outbound from inside the network, so nothing listens on the home IP. Cloudflare Access puts single sign-on in front of each private app.

  • Launcher: lists every app a signed-in user may open.
  • Domain: DNSSEC on, DMARC enforced.
02Front door

The tunnel was the moment this stopped feeling scary. Nothing is exposed at home, and I can still reach everything from anywhere.

03Network

Quiet traffic control for every device

Every device at home asks for directions before it goes anywhere online. A tiny computer answers those questions, and it refuses to give directions to ads and trackers.

03Network
Runs onPi-hole + Unbound

Filtered, recursive DNS for the whole network

The gateway handles routing and DHCP. DNS goes to Pi-hole, which forwards to Unbound as a local recursive resolver.

Device → Pi-hole → Unbound → root servers
  • Result: no third-party DNS provider, and ad and tracker domains are blocked for every device.
03Network

The day I turned on network-wide blocking, everything in the house got faster. Nobody noticed, which is exactly how infrastructure should work.
